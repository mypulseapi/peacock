# DESIGN.md — Pulse Design System

Source of truth for how every page and component in this project looks and reads.
Brand colours: **Signal** palette — `docs/pulse_brand_guidelines_final.md` §3–§6 is the source of truth for every value.
Typography: **Geist** + **Geist Mono** — the same guide, §8 (19 Oct 2026, replacing Inter).
Layout, components and voice: originally from the Google Stitch "Pulse Brand Guidelines System".
All tokens live in `src/input.css`.

Live reference: `components.html` shows every component below rendered with the real classes.

---

## 1. Principles

1. **Flat and typographic.** Matte, opaque fills. No glassmorphism, no glow, no decorative
   illustration or stock imagery. Depth comes from 1px borders, spacing and `shadow-sm` only.
   The only gradients are the Signal gradient (`bg-signal-gradient`), the calm gradient (`bg-calm-gradient`, the How it works progress line), the dark band gradient (`bg-void-gradient`), the soft gradient (`bg-soft-gradient`, the Why Pulse section) and the home hero's soft background (`hero-bg`) and coloured shadow (`hero-glow`), see §2.
2. **Data first.** Visual interest comes from tables, ranked lists, scores and status badges —
   not decoration.
3. **Colour has a job.** Every colour below has one meaning. Never use a colour outside its role.
4. **Generous whitespace.** Sections breathe (`py-20`); dense data lives inside cards.

## 2. Colour tokens — Signal

Every colour is defined once, in the `COLOURS` block of `@theme` in `src/input.css`. The values come from
`docs/pulse_brand_guidelines_final.md` §3–§5 (Signal; it replaces v2 Aurora); change them there first, then here.

1. **Brand palette** — `--brand-blue` (Pulse Blue), `--brand-red` (Signal Red), `--brand-sky` (Sky Blue), `--brand-ink`,
   `--brand-mist`, plus `--gradient-signal`, `--gradient-calm` and `--gradient-signal-fallback`. Not utilities — never use them in HTML.
2. **Roles** — what pages use (`primary`, `ink`, `gap` …). Every text and surface role is an **exact,
   contrast-checked hex** written as `light-dark(<light>, <dark>)` — never `color-mix()` for text, so the
   ratios in the guideline stay true. Only decorative borders and washes use `color-mix()`.
3. **Theme** — the page follows the visitor's OS setting (`color-scheme: light dark` on `:root`);
   `<html data-theme="light|dark">` overrides it. There is no visible toggle. Because every role is
   `light-dark()`, nothing else is needed for dark mode — no `dark:` classes in HTML. Dark surfaces are cool black
   (Night `#0B0D12`, cards `#14171F`), not navy (final guide, 19 Oct 2026). The one exception is what a token cannot switch,
   such as an image: use the `theme-dark:` variant (OS dark unless `data-theme="light"`, or `data-theme="dark"`),
   e.g. the reversed logo.

Rules:

- Use only the token classes below (`bg-primary`, `text-muted`, `border-line` …). Tailwind's default palette
  is switched off (`--color-*: initial`), so `bg-rose-500`, `text-white`, `bg-slate-100` don't exist —
  `pnpm lint:tw` reports them as `[unknownClass]`.
- Never write colour values in HTML or utilities: no hex, no `rgb()`, no `bg-[#…]`. Need a new colour?
  Add a **role-named** token to the `COLOURS` block (light and dark value, contrast-checked), then list it here.
- Name tokens by role, not hue (`primary`, not `indigo`), so names stay true when the palette changes.
- Opacity modifiers on tokens are fine for decoration (`bg-primary/70`), but **not on text** — `text-muted/60`
  or `opacity-60` on text drops it below 4.5:1.
- Check every new text/background pair with the WCAG formula (script, not estimate), in light **and** dark.

**Signal gradient:** `bg-signal-gradient` — Signal Red → Pulse Blue at 112°, blended in OKLCH (`--gradient-signal`), with an sRGB
fallback (`--gradient-signal-fallback`, via `@supports not`) for browsers without `in oklch`. Big brand moments only (hero or
closing CTA backgrounds, social, OG image) — at most one per page. **Text on it: white, large text only** (24px+, or 18.5px+
bold; white is 3.50 at the red end) — never body text or small labels, never Ink. Used once on the home page, blurred, as the
coloured shadow behind the hero demo (`hero-glow`).

**Calm gradient:** `bg-calm-gradient` — Sky → Pulse Blue (`--gradient-calm`), for product UI where red would read as an error.
Used for the How it works progress line. Same text rule.

**Hero background:** `hero-bg` — the page colour with a faint Sky wash (top right) and Pulse Blue wash (bottom left), plus a
soft primary light that follows the cursor (100ms ease, no visible lag) (`--hero-x` / `--hero-y`, set by `src/main.js`; mouse and pen only, not with
reduced motion). The light is a small (20rem) 14% circle with a solid core and a two-part tail: 6% / 4% copies that follow in 300ms / 600ms, so they trail behind a moving cursor like a comet. The tail shows only while the cursor moves (`--hero-tail` 1 → 0, 500ms fade, 150ms after it stops). At rest, light + wash (4%) keep `muted` text AA: 4.57 light / 6.26 dark.

**Dark band gradient:** `bg-void-gradient` — the `void` base with a soft Pulse Blue glow (top left) and Sky glow
(bottom right). Not used on any page at the moment (the home research band and How it works are light now); white and `void-muted` text stay AA
on its brightest point (13.88 / 5.90, the Sky glow).

**Soft gradient:** `bg-soft-gradient` — the page colour with 10% Pulse Blue (top left) and Sky (bottom right) washes; `muted`
stays AA where they overlap (4.66 light / 5.97 dark).

Status colours are **only** for audit status — never decorative.

## 3. Typography

Two faces from one family: **Geist** for headings and body, **Geist Mono** for data (Vercel, SIL OFL — `OFL.txt` beside them), chosen on 19 Oct 2026 from a test of three pairings on real Pulse components, in English and Vietnamese (replacing Inter 4.1; final brand guide §8). Self-hosted from `src/assets/fonts/geist/` (no Google Fonts link): variable weight 100–900, one file per subset (Latin, Latin Extended, Vietnamese; the browser loads only what a page uses); `@font-face` in `src/input.css`, Geist Latin preloaded in each page `<head>`. Body tracking −0.011em, headings lighter (550–600) and tighter (−0.01 to −0.022em, line height 1.1–1.35; a little air between heading lines). **Geist Mono only for data:** the values in data tables (every `<table>` sets Geist Mono with tabular figures; its first column, the product names, and the Missing flags stay in Geist) and numeric readouts such as the bit values on the Decision Audit page (`font-mono`). Never for prose, labels or headings. Until the fonts have loaded, "Geist Fallback" (Arial) and "Geist Mono Fallback" (Courier New), scaled to their metrics, show, so lines do not re-wrap. Tracking follows the size: −0.011em for body text (16px), −0.006em at 14px (`text-sm`, `text-data`), 0 at 12px (`text-xs`, `text-caption`), so small text stays open. Both faces have tabular figures (`tnum` in Geist, fixed-width digits in Geist Mono).

Rules:

- Numbers, SKUs, prices, percentages and any column of data → add **`tabular-nums`** so digits line up.
- `font-mono` (Geist Mono) only for data, never for prose, labels or headings. Load no other font (no Google Fonts link — Geist is self-hosted).
- Headlines and titles (`h1`–`h6`) are short, sentence case, and **never end with a full stop**, even when they are a
  statement ("Know which product data to fix first"; decided 19 Oct 2026). A full stop between two sentences in one
  heading stays ("Send one catalogue. Get the findings in 48 hours").

### Sizes — no flexible sizes inline

Responsive and one-off sizes belong in `@theme`, not in class attributes:

- **No arbitrary values** in HTML: no `w-[43.5%]`, `text-[10px]`, `min-w-[720px]`, `border-[1.5px]`.
- **Data widths are fractions of the real numbers**: `w-94/216`, `w-80/162` (Tailwind computes
  `calc(94 / 216 * 100%)`), so a bar is traceable to its source figures and never hand-rounded.
- **No breakpoint font sizes** (`sm:text-5xl lg:text-6xl`). Big headings use the fluid tokens, which scale
  with the viewport via `clamp()` defined once in `@theme`:

| Class                     | Size            | Use                                                                                                                                                                                                                                           |
| ------------------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text-display`            | 40 → 60px, 600  | Large page `h1` on future pages. Not used on the home page: every section heading there is `text-title` (36px)                                                                                                                                |
| `text-hero`               | up to 34px, 600 | Home hero `h1` only: `min(2.125rem, max(8.6cqi, 1.75rem))` (the rem floor lets it grow with text zoom; its lines are fixed only from `xl`), sized to its `@container` column so the two fixed lines always fit (33.6px at 1440, 29px at 1280) |
| `text-headline`           | 36 → 48px, 600  | Closing CTA heading                                                                                                                                                                                                                           |
| `text-title`              | 28 → 32px, 550  | Every home page section heading (two shelves, How it works, research, Why Pulse): one size for all                                                                                                                                            |
| `text-nav` / `text-label` | 15px / 12px     | Header links and buttons / small uppercase labels (table badges, dropdown section labels): 12px, 0.05em tracking                                                                                                                              |

Need a new responsive size? Add a fluid `--text-*` token (with line-height/weight/letter-spacing) to `@theme`.

## 4. Layout & spacing — the ruled frame

Pages use an Attio-style **ruled layout**: one centred column (no side lines), with every section
separated by a horizontal hairline.

```html
<section class="border-b border-line">
  <!-- full-width row, hairline below -->
  <div class="frame">
    <!-- centred column: frame = max-w-frame (70rem) + page margin -->
    <div class="py-16 lg:py-24">…</div>
    <!-- no px-*: the frame is the margin -->
  </div>
</section>
```

- Every section (and the header/footer inner row) wraps its content in `frame` so content edges line up.
  Dark bands use `bg-void` (or `bg-void-gradient`) on the section and `frame-dark` inside.
- Split content **inside** the frame with hairlines, not gaps: `grid … md:divide-x md:divide-line`,
  `divide-y divide-line`, or `border-t border-line` between a heading area and its visual.
- Visual areas (mockups, charts) sit on `blueprint-grid bg-surface-1/50`; text areas sit on the plain page.
- Padding: text areas `px-6 py-12 lg:px-12 lg:py-16`; big statements `py-24 lg:py-32`.
- Desktop grid: 12 columns (`lg:grid-cols-12`). Common splits: 3/9 (sticky nav + content), 5/7, 7/5.
- **The canvas outside the page is `card`** (`html` in base): when the page bounces past its top or bottom it shows the
  navbar / footer colour, never a strip of page colour above the sticky header.
- **No sideways scrolling, ever.** `<body class="overflow-x-clip">` on every page (`clip`, not `hidden`, so the
  sticky header keeps working). Content must also fit by itself: no `min-w-*` tables in sideways-scrolling boxes —
  hide less important columns on small screens instead (the hero demo tables show 2 attribute columns below `sm`,
  SKU from `lg`).
- At most one dark (`bg-void`) band per page.
- Inside cards: `p-6` (compact `p-4`/`p-5`), gaps `gap-4`–`gap-6`.
- Radius: `rounded-xl` cards and windows, `rounded-lg` buttons and inner panels, `rounded` chips,
  `rounded-full` badges and bars.
- Mobile first: every grid collapses to one column below `md`/`lg`; sticky side navs are `hidden lg:block`
  and replaced by an `eyebrow` step label (`01 · The problem`) above each block.
- Long headlines get `text-balance`, paragraphs `text-pretty` — no single-word last lines.

### Patterns

Section header (use for every `h2` section):

```html
<div class="mb-10 border-b border-line pb-4">
  <h2 class="text-h2">Section heading</h2>
</div>
```

Ranked list: only rank **#1** is solid `bg-signal` + `badge-signal` (value in `signal-text`); every other rank uses
solid `bg-baseline` (Slate) and neutral badges (`badge border-line text-muted`) — no fading tints.

Priority ring: the #1 row or column header gets `border-signal bg-signal-tint ring-1 ring-signal` (2px of Signal Red
with the border) and its rank shown in a `bg-signal text-on-step` square or in `signal-text`.

Emptiest vs deciding comparison: the field a traditional audit picks (the emptiest) is `baseline` (Slate) with neutral
text; the deciding field is `signal` with a direct text label.

Data table: wrapper `overflow-x-auto rounded-xl border border-line bg-card shadow-sm`;
`thead` `bg-surface-1 text-xs text-muted`; rows `divide-y divide-line`; values `tabular-nums text-data`;
empty values → `missing-cell`, not-applicable → `text-muted` "n/a".

Score / metric: big number in `font-display font-semibold`, unit or denominator in
`text-data text-muted tabular-nums` next to it.

Two-tone heading (Attio style) — a short statement in `ink`, the explanation continues in `muted`:

```html
<h3 class="text-h2">
  Two shelves, the same missing fact.
  <span class="text-muted">The shopper knows exactly what they need</span>
</h3>
```

Sticky step navigation: left `lg:col-span-3` column with `sticky top-16` nav; links carry
`data-spy="<section-id>"` and style the active state with `data-active:border-primary data-active:text-ink`
(set by `src/main.js`). Content blocks in `lg:col-span-9`, separated by `divide-y divide-line`.

Header / navbar (from thepulseapi.com): sticky, `h-17`, `bg-card`, bottom hairline. Logo `src/assets/brand/logo.webp`
(84×28) left, as two images: `logo.webp` with `theme-dark:hidden` and the reversed `logo-white.webp` (`alt=""`, `aria-hidden`) with `hidden theme-dark:inline`, so dark mode — OS or `data-theme` — and the dark band always show the white wordmark (footer included); menu `nav-link`s centred; language picker, Sign In and `btn-primary` CTA right; below `lg` a ☰ button
opens a full-screen menu. Dropdowns are native `<details data-dropdown>` — they work without JavaScript.
Mega menus (`<details data-dropdown data-mega>`): `[data-nav-content]` is `flex` with one
`nav-column w-76 p-3` column per group (light, inset divider between columns) — a small `text-xs text-muted` label, then items with a semibold `ink` title and a
one-line `text-sm text-pretty text-muted` description (keep it under ~35 characters); no intro panel, no icons
are taken over by `src/main.js` into one shared `nav-viewport` (attio.com style): the panel animates its
width/height (150ms, `ease-in-out-cubic`) and the contents slide ±200px with an 8px blur (200ms) in the direction
of travel. Give each menu's content a fixed width (`w-176`, `w-152` …) so the viewport can resize to it.
Copy the whole `<header>` from `index.html`. The shell starts with a `skip-link` ("Skip to content", visible on focus) to `<main id="main">`; the closing call to action sits inside `<main>`. Menu items whose page does not exist yet (Blog, Sign In, categories …) are `<a role="link" aria-disabled="true">` without `href` (not focusable, announced as unavailable links, muted, no hover or click), so they are not dead "#" links; give them the real `href` when the page exists.

Icons: Lucide-style stroke icons in an inline `<svg>` sprite at the top of `<body>`; use them with
`<svg class="size-4" aria-hidden="true"><use href="#i-name" /></svg>`. Add new icons to the sprite, never inline paths.

Product mockup: window `rounded-t-xl border border-b-0 border-line bg-card shadow-sm` with a
`h-10` title bar (three `size-2.5 rounded-full bg-line` dots + muted URL), sitting on `blueprint-grid`
and running into the section's bottom hairline. Use only real Pulse numbers in mockups.

Rules:

- **Reduced motion is mandatory.** `reveal`/`reveal-bar` already switch off; every `animate-*` class needs `motion-reduce:animate-none`.
- Never put `reveal` on an element that also has `transition-*` classes (they override each other) — wrap it instead.
- Content must be readable without JavaScript: put the final value in the HTML (`data-count` elements contain the real number).
- Classes added from JavaScript must live in `src/*.js` (scanned by `@source "./*.js"`).

## 7. Interaction & accessibility

- Hover: colour/border change only (`hover:bg-primary-hover`, `hover:text-ink`, `hover:border-ink`),
  `transition-colors duration-200 ease-out-soft`. No scale, lift or bounce on hover.
- Focus: 2px `focus` outline with a 2px offset on every interactive element (base `:focus-visible`; components add
  `focus-visible:outline-2 focus-visible:outline-focus`). Never remove outlines.
- Disabled: `disabled` attribute (styles are built in).
- Text contrast ≥ WCAG AA. `muted` on white is the lightest allowed body text.
- Every icon-only button needs `aria-label`; decorative SVGs get `aria-hidden="true"`; generated visuals
  (`data-shelf`) need `role="img"` and an `aria-label` with the real numbers.
- Use semantic elements (`header`, `main`, `section`, `article`, `nav`, `table`, `ol/ul`).

## 8. Voice & tone — "The Honest Data Analyst"

Quietly confident, empirical, calm. Peer to a merchandising lead.

| Do                                                                                             | Don't                                                           |
| ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Concrete numbers and direct cause: "Fixing bottle volume on 42 SKUs unblocks filtered search." | Vague AI magic: "Revolutionary AI supercharges your catalogue!" |
| State confidence and limits: "Confidence 82%. Not enough data beyond rank #4."                 | Unfalsifiable guarantees: "100% infallible."                    |
| Prioritise: "Fix the top 3 attributes first."                                                  | Dump everything with no priority.                               |
| Calm, plain English.                                                                           | Hype, jargon, emoji, exclamation marks.                         |

## 9. Never

- Gradients other than `bg-signal-gradient`, `bg-calm-gradient`, `bg-void-gradient`, `bg-soft-gradient` and `hero-bg`; glassmorphism, neon/glow shadows (exceptions: `hero-glow` behind the home hero demo, and the `shadow-glow` halo on the Why Pulse centre icon and selected circle), `shadow-lg`+ on light cards.
- Decorative looping animation (spinners, floating blobs, parallax); hover scale/lift effects.
- `signal` (Signal Red) more than once per view (two at most); red buttons; `gap` (amber) for anything that isn't missing data; `critical` for missing data or priority.
- Telling the two reds apart by colour alone: an error (`critical`) always carries the error icon (`#i-triangle-alert`) and a word; the #1 (`signal` / `signal-text`) always carries the priority ring and its rank number.
- Small or body text on the Signal gradient (white only, large text only); Signal Red, Sky or amber as text on light backgrounds (use `signal-text`, `link`, `gap-strong`); opacity reductions on text; Violet or Cyan decoration (Violet exists only inside the gradient).
- Colours outside the theme tokens; arbitrary `[…]` values or breakpoint font sizes in HTML (see §2, §3).
- Raw hex values or default Tailwind colours where a token exists.
- Monospace outside data (Geist Mono is for table values and numeric readouts only), extra font families, fonts or icon fonts loaded from a CDN.
- Inline `style=""` or new `<style>` blocks in HTML — add to `src/input.css` instead.
